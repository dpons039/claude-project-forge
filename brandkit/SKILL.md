# BrandKit

Permanent per-project skill managing a dev-only design-system page and its
satellite docs. The page shows every design decision rendered next to the code
that produces it; the docs hold the reasoning. This skill keeps both coherent.

Not a design-authoring skill: it documents and verifies the design system, it
does not invent one. The "exactly ONE design skill per project" rule does not
apply to it.

## The satellites

| Artefact | Role |
|---|---|
| `frontend/brandkit.html` + `frontend/src/brandkit/` | The page — dev-only **by construction** (entry absent from build inputs) |
| `docs/BrandKit.md` | How the page works, how to add blocks — **owned by this skill** |
| `docs/design.md` | Tokens, hierarchy, themes — reasoning upstream of the page |
| `docs/voice.md` | Tone, vocabulary — source of every specimen string |
| `PRODUCT.md` (root) | Product context (impeccable v4); § Brand Commitments names mark/colour/type/a11y |

The page shows; it does not decide. When page and docs disagree, the doc is
right and the page is the bug.

## Operation Detection

1. Check what exists: `docs/BrandKit.md`? A page (`src/brandkit/` or a brandkit
   entry next to the app's index)?
2. Route:
   - Neither exists → **init-docs**; then offer **init-page** if a **web**
     frontend exists (a desktop GUI is not one — init-page needs a build with
     declarable entries).
   - Doc exists, no page → **init-page**.
   - Both exist and the user wants a change → **update**.
   - Both exist and the user wants a health check → **audit**.
   - Ambiguous trigger ("check the brandkit", "brandkit is stale") → **audit**
     (read-only, safest default).

## Operation 1 — init-docs

Works **without a frontend**. Creates `docs/BrandKit.md` from the template;
stubs `docs/design.md` / `docs/voice.md` only if missing; appends
§ Brand Commitments to an existing `PRODUCT.md` if that section is missing.
Never overwrites an existing file — an existing `BrandKit.md` is `update`
territory. `PRODUCT.md` itself is generated by `/impeccable teach`
(project-bootstrap), never by this skill.

Read `references/init-docs-guide.md`.

## Operation 2 — init-page

Requires a working frontend. Generates the page — no code is shipped by this
skill — with the canonical architecture: a **separate build entry excluded
from production by construction**, its own root, one file per tab, shared
components, live tokens read from the real stylesheet, zero hardcoded values.

The heading set is `templates/page/page-structure.md` (7 tabs — 6 fixed + 1
domain — and the canonical blocks per tab, including `Iconography` and
`Motion` in Foundations). Skipping a canonical heading requires a
"skipped: <reason>" note in `BrandKit.md`.

Read `references/init-page-guide.md`.

## Operation 3 — update

Any change to the system — new block, new wireframe, token change, copy
change, new accent or theme, new UI language, removal — walks the
**cross-update table** so page, `BrandKit.md`, `design.md`, `voice.md` and
`PRODUCT.md` move together. Never stop at "the page is updated".

Read `references/update-guide.md`.

## Operation 4 — audit

Read-only. Runs 16 mechanical checks (gating, live tokens, block inventory,
string provenance, wireframe corrections, transcribed numbers, encapsulation,
canonical coverage, doc coherence, size caps) and produces a findings report
with cited evidence. Applies **no fixes** — fixes are a follow-up task the
report feeds.

Read `references/audit-checklist.md`.

## Templates

| Template | Installs to | Type |
|----------|------------|------|
| `templates/docs/BrandKit.md.template` | `docs/BrandKit.md` | Placeholders |
| `templates/docs/design.md.template` | `docs/design.md` (only if missing) | Stub, placeholders |
| `templates/docs/voice.md.template` | `docs/voice.md` (only if missing) | Stub, placeholders |
| `templates/docs/PRODUCT-brand-section.md.template` | appended to `PRODUCT.md` | Section stub, placeholders |
| `templates/page/page-structure.md` | not copied — outline `init-page` generates from and `audit` checks against | Headings only |

Files ending in `.template` have `[PLACEHOLDERS]`. **This skill ships no page
code**: `templates/page/` holds only the canonical heading structure (the
merge of both reference implementations); the code is generated per project
by `init-page`, carrying the debugged techniques listed in its guide.

## Assumptions

Vite-family build (explicit entry list → a sibling HTML entry is simply never
built) and a React-family component model — the guide's mechanisms assume
them. Different stack → read `references/init-page-guide.md`
§ Adapting to a different stack for the principle and generate equivalents;
the heading structure is stack-independent.
