# init-docs — create the satellite docs (no frontend required)

Creates the documentation half of the BrandKit. Safe to run on a project whose
frontend does not exist yet; the page half comes later with `init-page`.

## Step 1 — Detect project facts

Read, in this order, whatever exists:

- `CLAUDE.md` — languages and stack, under Conventions. **Two language
  dimensions matter**: the written-artifacts language (code + docs + comments
  + commits — the satellites and the page chrome are written in it) and the
  UI language (the examples). The current convention form declares both
  ("everything written is English… the app interface (Spanish…)"); an OLDER
  form declares only the code language — in that case do NOT assume docs
  follow it: read how `docs/` is actually written and confirm with the user
  if they differ.
- `docs/README.md` — which area docs are already indexed.
- Presence of `docs/design.md`, `docs/voice.md`, `docs/BrandKit.md`,
  `PRODUCT.md` (root).

## Step 2 — Ask only what cannot be inferred

- **Domain tab name** — the 7th tab is project-specific (a reference project: "Data &
  money"). No file states it; ask. A project may also have none — then the 6
  fixed tabs are the set.
- Languages, if there is no `CLAUDE.md` — or if it only declares a code
  language and the actual `docs/` language differs from it.

## Step 3 — Create docs/BrandKit.md

From `templates/docs/BrandKit.md.template`, filling `[PROJECT_NAME]`,
`[UI_LANG]`, `[DOMAIN_TAB_NAME]`. `[DEV_URL_PATH]` stays "TBD until init-page
runs" if the page does not exist yet.

**Output language** (this step and steps 4-6): the project's
written-artifacts language. The templates' English is the source structure,
not the output language — a project whose docs are Spanish gets its
satellites in Spanish.

**Never overwrite an existing `docs/BrandKit.md`.** If present, stop: that is
`update` territory, not init — including the case where a satellite
(design.md, voice.md) is missing beside an existing BrandKit.md: report it,
don't create it here.

## Step 4 — docs/design.md

Only if the area applies — the canonical contract marks `design.md`
conditional ("if project has a design system"). A CLI or desktop utility
without one skips this step.

- Exists → do not touch.
- Missing (and applies) → stub from `templates/docs/design.md.template`:
  section skeleton with "Pending definition" placeholders. Flag it, don't
  invent values.

## Step 5 — docs/voice.md

Same rules — conditional on the product having user-facing copy. Stub from
`templates/docs/voice.md.template` (address/register, voice qualities, domain
vocabulary, errors, empty states, destructive confirmation).

## Step 6 — PRODUCT.md (root)

This file is **owned by impeccable** (`/impeccable teach`, see
project-bootstrap step 16). This skill never creates it.

- Exists, has `## Brand Commitments` → do not touch.
- Exists, section missing → append from
  `templates/docs/PRODUCT-brand-section.md.template`.
- Missing → tell the user: "PRODUCT.md is generated by `/impeccable teach` —
  run that first; brandkit only maintains its § Brand Commitments."

## Step 7 — Index

Add a `BrandKit.md` row to `docs/README.md` if that index exists (project
rule: new file in docs/ → update README.md).

## Step 8 — Summary

List created / stubbed / left alone. If no page exists yet: "Run `init-page`
when the frontend exists." If `.claude/doc-coverage.json` exists, note that
`init-page` will add the page → BrandKit.md warning trigger.
